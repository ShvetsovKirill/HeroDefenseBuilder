Ссылки вида **D12** — на решения из плана.

## Инварианты — нарушать нельзя

Это не стиль, а требования, которые легко сломать по незнанию и трудно заметить на ревью.

| Правило | Откуда | Что будет, если нарушить |
|---|---|---|
| **У врага нет своего `Update`** | производительность | Движение и атака врагов идут одним циклом в `EnemyManager`. Добавить `Update` на `Enemy` — значит вернуть сотни вызовов за кадр. |
| **Общие системы только через `SceneContext`** | D26, ревью | `FindFirstObjectByType` был разбросан по семи классам и ломался бы при смене карты. Сейчас все ссылки на `EnemyManager`, `Wallet`, `TownHall`, `King` идут через контекст. Заводить своё поле — значит создать второй источник правды. |
| **Числа контента — в ассетах, не в коде** | D48 | `EnemyDefinition`, `WaveDefinition`, `BuildingDefinition`, `KingDefinition`. Дизайнер крутит их без пересборки. Захардкодить число в скрипте — значит вернуть его через программиста. |
| **Логика не знает о рендере** | D10 | Ни один геймплейный скрипт не лезет в `Animator`, кости или меш. Когда появятся анимации, между ними встанет компонент-посредник. |
| **Ни одного вызова `YG2.` из геймплея** | D24 | Только внутри реализации `IPlatformServices`. Иначе сборка под Steam превратится в выкорчёвывание вызовов из десятков файлов. |
| **`Time.timeScale` трогает только `GameState`** | ревью | Он глобальный и переживает смену сцены. Одно исключение — явный сброс в `GameLoop.Restart()` перед загрузкой. |
| **Параметры короля читаются из `KingStats`** | эпик короля, шаг 1 | Не из `[SerializeField]` компонентов. Иначе прокачка (D66) не сможет их менять. |

## Что где лежит

### Core — инфраструктура

| Класс | Что делает |
|---|---|
| `SceneContext` | Единая точка доступа к системам карты. `[DefaultExecutionOrder(-1000)]`, статический `Current`, обнуляется при выгрузке. |
| `GameState` | Фазы партии: Playing / Paused / Defeat / Victory. Владеет `timeScale`. Все игровые системы проверяют `IsPlaying`. |
| `GameLoop` | Связывает события с фазами: ратуша разрушена → Defeat, волны кончились → Victory. Escape — пауза, Enter — рестарт. |
| `Health` | Общий компонент здоровья для ратуши, построек, бойцов (D40). Ничего не знает про поражение — это знание уровнем выше. |
| `PlayfieldBounds` | Границы поляны (D70). Круг или прямоугольник, метод `Clamp`. Гизмо в сцене. |
| `GameBootstrap` | Composition root: выбирает реализацию `IMovementInput`. Единственное место, знающее про конкретный ввод. |

### King — король

| Класс | Что делает |
|---|---|
| `KingDefinition` | ScriptableObject: статы, оружие, портрет, префаб визуала, цвет коня. Новый король = новый ассет (D60). |
| `KingStats` | Runtime-слой: `(база + плоские бонусы) × множители`. Плоские первыми — иначе порядок покупки апгрейдов влиял бы на результат. Множители складываются, а не перемножаются. |
| `King` | Владелец `KingStats`, спавнит визуал из дефиниции, событие `StatsChanged`. |
| `KingCombatBinder` | Переливает статы в `AutoAttacker`. Отдельный компонент, потому что тот же `AutoAttacker` висит на башнях и бойцах, которым про короля знать незачем. |

### Hero — движение

| Класс | Что делает |
|---|---|
| `HeroMotor` | Движение по XZ с инерцией (D37). Числа из `KingStats`. Направление относительно камеры. Удерживается в `PlayfieldBounds`. |
| `IMovementInput` / `KeyboardMovementInput` | Контракт ввода (D20). Клавиатура сегодня, тап завтра — герой не меняется. |
| `IsometricCameraFollow` | Фиксированный угол, следование за целью с `SmoothDamp`. |

### Enemies — враги

| Класс | Что делает |
|---|---|
| `Enemy` | Состояние (Moving / Attacking), HP, урон, `Version` для защиты от переиспользования из пула. **Своего `Update` нет.** |
| `EnemyManager` | ⚠️ 525 строк, делает три вещи: пул-менеджмент, расталкивание, поведение. Кандидат на разделение. |
| `EnemyPool` | Переиспользование объектов. В WebGL сборка мусора видна как рывки. |
| `SpatialGrid` | Не MonoBehaviour. Равномерная сетка для поиска соседей: 90 000 проверок превращаются в десятки. |

### Combat

| Класс | Что делает |
|---|---|
| `AutoAttacker` | Общий для короля, башен и бойцов. Два режима: ищет цель сам (король, башни) или получает извне через `TakeTargetControl()` + `SetTarget()` (бойцы). Хитскан и снаряды: `Projectile` и `ProjectilePool` уже написаны. |

### Squads — отряды

| Класс | Что делает |
|---|---|
| `SquadUnit` | Боец: якорь у флага, `engageRadius` (уйти драться) отдельно от `attackRange` в `AutoAttacker` (D13). Расталкивание через `OverlapSphere` — **нужен коллайдер с Is Trigger**. |
| `Squad` | Список бойцов, позиция флага, построение кольцом. Флаг `_isDisbanding` защищает от событий смерти во время роспуска. |
| `Barracks` | Производит отряд, пополняет по шкале за золото (D21a). Оплата вперёд — иначе бойцов можно получить даром. |
| `BarracksDefinition` | Тип отряда, размер, цена бойца, цвет флага. |
| `FlagController` | Клавиши 1–4 и F (D51). Знамя в руках короля вместо превью на земле (D52). Чистит маркеры разрушенных казарм. |

### Building — застройка

| Класс | Что делает |
|---|---|
| `BuildSlot` | Фиксированная точка (D3). Состояния подсветки, проверка `IsContested` — нельзя строить в бою. |
| `BuildController` | Фокус по подъезду короля, не по клику. Каталог построек, событие `BuildingPlaced`. |
| `BuildingDefinition` | Цена, префаб, иконка, категория. |
| `BuildPanelView` / `BuildCardView` | Панель с карточками. ⚠️ Скрипт и выключаемая панель — **разные объекты**, иначе панель выключит саму себя. |

### Waves — волны

| Класс | Что делает |
|---|---|
| `EnemyDefinition` | HP, скорость, награда, вес угрозы. |
| `SpawnGroup` (в `WaveDefinition.cs`) | Кирпичик: кого, сколько, откуда, с каким интервалом. **`interval` — главная ручка плотности** (D55). |
| `WaveDefinition` | Набор групп с задержками. Из них собирается любая форма атаки. |
| `LevelDefinition` | Последовательность волн + метод `BuildPreview()`. |
| `WaveRunner` | Проигрывает уровень корутинами. Ничего не решает про баланс. |
| `LevelDefinitionEditor` | Кнопка превью в инспекторе (D56). Лежит в папке `Editor/` — обязательно. |

### UI

| Класс | Что делает |
|---|---|
| `GameHud` | TMP. Золото и волна по событиям, HP и счётчик врагов каждый кадр. |

### Localization — языки

Своя лёгкая система вместо пакета Unity Localization: тот тянет Addressables
и таблицы, а здесь нужен словарь на два языка.

| Класс | Что делает |
|---|---|
| `Language` | Перечисление языков. **Значения пишутся в сохранение числом** — порядок менять нельзя, новые языки только в конец. |
| `LocalizationTable` | ScriptableObject с ключами и переводами. Тексты — контент, их правит не программист (D48). Лежит в `Resources`, иначе не загрузится. |
| `Loc` | Статический доступ. Таблица грузится сама при первом обращении — чтобы сцена, запущенная напрямую из редактора, не показывала голые ключи. Язык хранится в PlayerPrefs, по умолчанию английский. |
| `LocalizedText` | На надписи с неизменным текстом: подписи кнопок, заголовки. Строки с числами собираются в коде через `Loc.Get(key, args)`. |

**Пропуск виден сразу:** неизвестный ключ показывается как есть (`menu.newgame`),
пустой перевод откатывается на английский, пустой английский — на ключ.

⚠️ **Не локализованы названия построек и улучшений.** Они лежат строками
в `BuildingDefinition.displayName` и `UpgradeDefinition`. Чтобы перевести,
в дефиниции нужно поле с ключом вместо готового текста.

## Техдолг — с причинами

### 1. `EnemyManager` делает три вещи (525 строк)

Сейчас в одном классе: пул-менеджмент (спавн, смерть, `_alive`), расталкивание (сетка, вычисление смещений), поведение (движение, переход в осаду).

Разделение **сначала обсудить**, потом делать. Ориентир: вынести расталкивание в отдельный сервис, поведение оставить, пул-менеджмент оставить. Но резать надо так, чтобы не появилось лишних проходов по списку живых — сейчас он один.

### 2. Раскладка папок ~~разъехалась с namespace~~ — разобрано 4 сентября 2026

Свалка `Addition/` разобрана, `Enemy/` и `Level/` расформированы, `LevelDefinition.cs` переехал из `ScriptableObjects/` в `Waves/`. Ассеты волн уехали из `Scripts/Waves/` в `Assets/WaveResources/` — это контент, ему не место в папке с кодом.

Сейчас **папка = namespace** соблюдается без исключений:

```
Scripts/App        App/UI      Base       Building   Building/UI
CameraRig          Combat      Core       Debugging  Diagnostics
Economy            Enemies     Hero       Input      King
Meta               Squads      UI         Visuals    Waves (+ Waves/Editor)
```

Правило теперь не пожелание, а состояние: новый файл кладётся в папку своего namespace, иначе раскладка снова поедет.

### 3. Разрушаемость построек не написана

`Health` под неё готов, решения записаны (D40–D44), но поведения врагов нет: они идут только к ратуше и ломают только её.

### 4. Flow field отсутствует

Враги идут по прямому вектору к цели. Точка замены помечена в коде — `EnemyManager.ResolveDirection()`. Без flow field не работает D84–D85 (шахматная застройка, обход препятствий).

### 5. Нет координатора экранов

Пауза, победа, поражение переключаются через `SetActive`. При добавлении перебивки между актами и экрана прокачки начнут накладываться. Нужен слой, который знает, какой модальный экран открыт, и гасит контекстные панели.

### 6. Враги и союзники не расталкивают друг друга

Механизмы разные: враги — через `SpatialGrid`, союзники — через `OverlapSphere`. Внутри своей фракции всё работает, между фракциями — проходят насквозь. Может быть заметно в ближнем бою.

Варианты: дать врагам триггер-коллайдер и учитывать их в `SquadUnit` (дёшево, асимметрично) или свести обе фракции в одну сетку (правильно, дороже).

### 7. Мёртвый код

`Squad.DisbandAll()` — не вызывается нигде. `Squad.commanderId` — зарезервирован под D19, не используется. `Barracks.IsBuilding`, `Barracks.BuildProgress` — под будущий индикатор над постройкой. `Enemy.Deactivate()`.

Не удалять бездумно: часть зарезервирована осознанно.

## Что не трогать без просьбы

**Конструктор волн.** Работает, настраивается дизайнером через ассеты. Менять API — значит ломать уже собранные уровни.

**`SceneContext` и `GameState`.** Только что введены после ревью, на них завязано всё остальное.

**Файлы Unity.** `.unity`, `.prefab`, `.asset`, `.meta` — не редактировать как текст. Новый скрипт = новый `.meta`, который сгенерирует только редактор.

## Правила работы

**Одна задача за раз.** Диф на 400 строк невозможно осмысленно проверить.

**Крупное — сначала план.** Разрезание `EnemyManager`, координатор экранов, flow field — сначала согласовать разбиение.

**Не «заодно».** Заметил постороннее — вынести отдельной задачей.

**Ссылаться на номера решений.** «Сделай D85» точнее, чем «сделай обход препятствий»: в решении есть и формулировка, и предупреждение про maze-abuse.

**Держать правило гейтов.** Не писать код эпика, пока не пройден гейт предыдущей фазы. Сейчас не пройден **Гейт 1** — способности, прокачка и мета кодом не трогаются.

**Комментарии на русском, объясняют «почему», а не «что».** Ссылка на решение в скобках, если оно есть: `// Оплата вперёд (D21a): иначе бойцов можно получить даром`.
