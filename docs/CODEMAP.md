Дополнение к `HeroDefense_Builder_Plan_v7.md`. План отвечает на «что» и «почему», этот файл — на «как устроен код сейчас».

Ссылки вида **D12** — на решения из плана.

## Инварианты — нарушать нельзя

Это не стиль, а требования, которые легко сломать по незнанию и трудно заметить на ревью.

| Правило | Откуда | Что будет, если нарушить |
|---|---|---|
| **У врага нет своего `Update`** | производительность | Движение и атака врагов идут одним циклом в `EnemyManager`. Добавить `Update` на `Enemy` — значит вернуть сотни вызовов за кадр. |
| **Общие системы только через `SceneContext`** | D26, ревью | `FindFirstObjectByType` был разбросан по семи классам и ломался бы при смене карты. Сейчас все ссылки на `EnemyManager`, `Wallet`, `TownHall`, `King` идут через контекст. Заводить своё поле — значит создать второй источник правды. |
| **Числа контента — в ассетах, не в коде** | D48 | `EnemyDefinition`, `WaveDefinition`, `BuildingDefinition`, `KingDefinition`. Дизайнер крутит их без пересборки. Захардкодить число в скрипте — значит вернуть его через программиста. |
| **Логика не знает о рендере** | D10 | Ни один геймплейный скрипт не лезет в `Animator`, кости или меш. Когда появятся анимации, между ними встанет компонент-посредник. |
| **Ни одного вызова `YG2.` из геймплея** | D24 | Только внутри реализации `IPlatformServices`. Иначе сборка под Steam превратится в выкорчёвывание вызовов из десятков файлов. |
| **`Time.timeScale` трогает только `GameState`** | ревью | Он глобальный и переживает смену сцены. Исключения — только сброс в единицу перед загрузкой сцены: `GameLoop.Restart()`, `PauseScreen`, `SceneLoader.LoadRoutine`. Сцена, загруженная при нуле, встаёт намертво вместе с корутинами загрузчика. |
| **Параметры короля читаются из `KingStats`** | эпик короля, шаг 1 | Не из `[SerializeField]` компонентов. Иначе прокачка (D66) не сможет их менять. |

## Что где лежит

### Core — инфраструктура

| Класс | Что делает |
|---|---|
| `SceneContext` | Единая точка доступа к системам карты. `[DefaultExecutionOrder(-1000)]`, статический `Current`, обнуляется при выгрузке. |
| `GameState` | Фазы партии: Playing / Paused / Defeat / Victory. Владеет `timeScale`. Все игровые системы проверяют `IsPlaying`. |
| `GameLoop` | Связывает события с фазами: ратуша разрушена → Defeat, волны кончились → Victory. Escape — пауза, Enter — рестарт. |
| `Health` | Общий компонент здоровья для ратуши, построек, бойцов (D40). Ничего не знает про поражение — это знание уровнем выше. |
| `PlayfieldBounds` | Границы поляны (D70). Круг или прямоугольник, метод `Clamp`. Гизмо в сцене. |
| `GameBootstrap` | Composition root: выбирает реализацию `IMovementInput`. Единственное место, знающее про конкретный ввод. |

### King — король

| Класс | Что делает |
|---|---|
| `KingDefinition` | ScriptableObject: статы, оружие, портрет, префаб визуала, цвет коня. Новый король = новый ассет (D60). |
| `KingStats` | Runtime-слой: `(база + плоские бонусы) × множители`. Плоские первыми — иначе порядок покупки апгрейдов влиял бы на результат. Множители складываются, а не перемножаются. |
| `King` | Владелец `KingStats`, спавнит визуал из дефиниции, событие `StatsChanged`. |
| `KingCombatBinder` | Переливает статы в `AutoAttacker`. Отдельный компонент, потому что тот же `AutoAttacker` висит на башнях и бойцах, которым про короля знать незачем. |

### Hero — движение

| Класс | Что делает |
|---|---|
| `HeroMotor` | Движение по XZ с инерцией (D37). Числа из `KingStats`. Направление относительно камеры. Удерживается в `PlayfieldBounds`. |
| `IMovementInput` / `KeyboardMovementInput` | Контракт ввода (D20). Клавиатура сегодня, тап завтра — герой не меняется. |
| `IsometricCameraFollow` | Фиксированный угол, следование за целью с `SmoothDamp`. |

### Enemies — враги

| Класс | Что делает |
|---|---|
| `Enemy` | Состояние (Moving / Attacking), HP, урон, `Version` для защиты от переиспользования из пула. **Своего `Update` нет.** |
| `EnemyManager` | ⚠️ 525 строк, делает три вещи: пул-менеджмент, расталкивание, поведение. Кандидат на разделение. |
| `EnemyPool` | Переиспользование объектов. В WebGL сборка мусора видна как рывки. |
| `SpatialGrid` | Не MonoBehaviour. Равномерная сетка для поиска соседей: 90 000 проверок превращаются в десятки. |

### Combat

| Класс | Что делает |
|---|---|
| `AutoAttacker` | Общий для короля, башен и бойцов. Два режима: ищет цель сам (король, башни) или получает извне через `TakeTargetControl()` + `SetTarget()` (бойцы). Хитскан и снаряды: `Projectile` и `ProjectilePool` уже написаны. |

### Squads — отряды

| Класс | Что делает |
|---|---|
| `SquadUnit` | Боец: якорь у флага, `engageRadius` (уйти драться) отдельно от `attackRange` в `AutoAttacker` (D13). Расталкивание через `OverlapSphere` — **нужен коллайдер с Is Trigger**. |
| `Squad` | Список бойцов, позиция флага, построение кольцом. Флаг `_isDisbanding` защищает от событий смерти во время роспуска. |
| `Barracks` | Производит отряд, пополняет по шкале за золото (D21a). Оплата вперёд — иначе бойцов можно получить даром. |
| `BarracksDefinition` | Тип отряда, размер, цена бойца, цвет флага. |
| `FlagController` | Клавиши 1–4 и F (D51). Знамя в руках короля вместо превью на земле (D52). Чистит маркеры разрушенных казарм. |

### Building — застройка

| Класс | Что делает |
|---|---|
| `BuildSlot` | Фиксированная точка (D3). Состояния подсветки, проверка `IsContested` — нельзя строить в бою. |
| `BuildController` | Фокус по подъезду короля, не по клику. Каталог построек, событие `BuildingPlaced`. |
| `BuildingDefinition` | Цена, префаб, иконка, категория. |
| `BuildPanelView` / `BuildCardView` | Панель с карточками. ⚠️ Скрипт и выключаемая панель — **разные объекты**, иначе панель выключит саму себя. |

### Waves — волны

| Класс | Что делает |
|---|---|
| `EnemyDefinition` | HP, скорость, награда, вес угрозы. |
| `SpawnGroup` (в `WaveDefinition.cs`) | Кирпичик: кого, сколько, откуда, с каким интервалом. **`interval` — главная ручка плотности** (D55). |
| `WaveDefinition` | Набор групп с задержками. Из них собирается любая форма атаки. |
| `LevelDefinition` | Последовательность волн + метод `BuildPreview()`. |
| `WaveRunner` | Проигрывает уровень корутинами. Ничего не решает про баланс. |
| `LevelDefinitionEditor` | Кнопка превью в инспекторе (D56). Лежит в папке `Editor/` — обязательно. |
| `WaveModifier` | Условие волны: множители числа, плотности, HP, скорости врагов и награды. Контент, ассет. |
| `WaveModifierSet` | Набор условий в `Resources` плюс правила показа: сколько вариантов, с какой волны. Нет ассета — выбора нет, всё работает как раньше. |
| `WaveModifiers` | Статика: какое условие действует сейчас. Читают спавн врагов, раннер и кошелёк. Условие живёт **ровно одну волну**. |
| `WaveModifierPicker` (в `UI`) | Экран выбора в перерыве и плашка действующего условия. Создаётся сам. |

**Конструктор волн условиями не тронут.** Множители применяются поверх
собранной волны в трёх точках: `WaveRunner.RunGroup` (сколько и как плотно),
`EnemyManager.Spawn` (HP и скорость при рождении), `Wallet.OnEnemyKilled`
(награда). Данные `SpawnGroup` и `WaveDefinition` остались прежними,
собранные уровни продолжают работать.

### Campaign — кампания

Слой над боем: карта владений, армия между забегами, награды.
Ничего из этого не знает про боевые классы — только про данные.

| Класс | Что делает |
|---|---|
| `HoldingDefinition` | Одно владение: тип, фракция, набор волн, награды. Бой не переизобретает — ссылается на готовый `LevelDefinition`. |
| `CampaignMapDefinition` | Карта слоями слева направо. Связи только вперёд — **назад дороги нет**, и `OnValidate` ругается на связь вбок или назад. |
| `CommanderDefinition` | Командир: имя, портрет, заметные бонусы отряду, список специализаций, которые умеет вести. |
| `SquadRecord` | Учётная запись отряда в армии: слот, командир, специализация. Не путать с боевым `Squad` — тот живёт один забег. |
| `CampaignState` | Всё, что переживает бой: армия, путь, колода, свободные командиры. Сериализуется в JSON. |
| `CampaignRun` | Доступ к текущей кампании и сохранение в PlayerPrefs. Битое сохранение не роняет игру. |
| `CampaignRules` | Числа похода: стартовая армия, потолки, колода, пул командиров. Ассет в `Resources`. |
| `CampaignFlow` | Переходы: выбор владения, запуск боя, разбор итога, выдача наград. Вся логика похода в одном месте. |
| `CampaignBattleBridge` | На боевой сцене: подставляет уровень владения и сообщает итог. Нет кампании — удаляет себя, и сцена работает сама по себе. |
| `CampaignArmy` | Раздаёт казармам отряды из армии похода и накладывает бонусы командира поверх прокачки. Вне кампании молчит. |
| `CampaignMapView` (в `Campaign/UI`) | Экран карты. Каркас под арт: показывает тип владения, фракцию и награду **до** входа. |
| `ArmyScreen` (в `Campaign/UI`) | Войско в лагере: кому отдать свободного командира, что делать с осиротевшим отрядом. Открывается кликом по казармам. |

**Казарма перестала быть фабрикой.** В походе `Barracks` не придумывает
отряд, а получает готовую запись из армии: размер, командир,
специализация. Вне похода работает как раньше — боевую сцену запускают
напрямую сотню раз за день.

**Командир выходит даром и один раз.** Он не рекрут: появляется сразу
при постройке казармы, минуя шкалу пополнения и оплату, идёт сверх штата
и заметно живучее рядовых. `CommanderMark` следит за его смертью —
погибший не возвращается ни в этом бою, ни в следующем владении.

**Смерть командира ≠ смерть отряда.** Выбитый отряд теряет имя
и специализацию (`SquadRecord.LoseCommander`), люди набираются заново
за золото, а судьбу отряда игрок решает в лагере: дать нового командира
или разжаловать в ополчение.

**Потолок не выдаётся сразу.** Девять отрядов и большой отряд — то,
к чему игрок идёт за престиж; начинает он с двумя отрядами по шесть.

### UI

| Класс | Что делает |
|---|---|
| `GameHud` | TMP. Золото и волна по событиям, HP и счётчик врагов каждый кадр. |
| `ControlsInfo` | Единственный список клавиш в игре. Читают подсказка, пауза и окно из меню — три копии разъехались бы при первой же смене клавиши. |
| `RuntimeUi` | Сборка простых панелей кодом: канвас, панель, текст, кнопка. Не замена вёрстке — служебные экраны, которых иначе пришлось бы держать в каждой сцене. |
| `ControlsHint` | Подсказка в левом нижнем углу первые 14 секунд боя. Гаснет сама, на паузе не тикает. |
| `PauseScreen` | Экран паузы: клавиши, «продолжить», «заново», «выйти в замок». Создаётся сам на каждой карте с `GameState`. |
| `ControlsScreen` | То же окно клавиш из главного меню. Открывается методом `ControlsScreen.Show()`. |
| `LoadingScreen` (в `App/UI`) | Затемнение с полоской на переходах. Подписан на `SceneLoader`, живёт между сценами. |
| `MainMenuLogo` (в `App/UI`) | Название игры над кнопками меню. Спрайт из `UiSkin`, вёрстка не нужна. Нет картинки — компонент удаляет себя. |
| `UiSkin` | Ассет в `Resources` со спрайтами служебных экранов: рамки, кнопка, полоска, картинки клавиш, логотип. Нет ассета — экраны рисуются заливкой, как раньше. |
| `ButtonTextFitter` | Держит поля между подписью кнопки и её краем: ставит margin и разрешает ужимать кегль. Кнопки свёрстаны под русский, а он короче английского. Проходит по всем кнопкам сцены при загрузке, включая выключенные панели. |

⚠️ **`ContentSizeFitter` не ставится внутри чужой раскладки.** Фиттер
и родительская `LayoutGroup` спорят за высоту, объект схлопывается в ноль,
и от списка на экране остаётся последняя строка, а от панели — угол рамки.
Высоту вложенной колонки считает родительская группа: она умеет спрашивать
вложенную. Наступали 5 сентября 2026 — пауза и подсказка управления
выглядели как случайный мусор поверх боя.

**Служебные экраны создают себя сами** через `RuntimeInitializeOnLoadMethod`
и `SceneManager.sceneLoaded`. Причина: ставить их руками в каждую сцену —
значит однажды забыть в одной, и пропажа выглядит не как ошибка, а как
«тут просто ничего нет».

### Audio — звук

| Класс | Что делает |
|---|---|
| `SoundId` | Перечисление звуковых событий. Не строки: опечатка в строке даёт тишину, которую находят только на слух. |
| `AudioCatalog` | ScriptableObject: событие → клипы, громкость, разброс тона, **минимальный интервал**. Лежит в `Resources`, иначе не загрузится. |
| `AudioService` | Пул из 16 источников, музыка с переходом. Создаёт себя при первом обращении и переживает смену сцен. |
| `Sfx` | Короткий фасад: `Sfx.Play(SoundId)` и `Sfx.PlayAt(id, position)`. |
| `AudioOptions` | Три громкости в PlayerPrefs: общая, музыка, эффекты. |
| `SceneAudio` | Слушает события боя и включает трек сцены. Создаётся сам при загрузке любой сцены. |
| `UiClickSound` | Щелчок кнопок. Вешается на корень экрана — озвучит все кнопки внутри. |

**Главная ручка против каши — `minInterval` в каталоге.** Сорок врагов
умирают в одну секунду, и без ограничения сорок копий одного файла
складываются в треск.

**Звук вызывается из геймплея в трёх местах:** `AutoAttacker` (удар —
зависит от оружия, поэтому поле на префабе), `SquadUnit` (смерть бойца),
`Barracks` и `FlagController`. Остальное слушает `SceneAudio` со стороны.

### Localization — языки

Своя лёгкая система вместо пакета Unity Localization: тот тянет Addressables
и таблицы, а здесь нужен словарь на два языка.

| Класс | Что делает |
|---|---|
| `Language` | Перечисление языков. **Значения пишутся в сохранение числом** — порядок менять нельзя, новые языки только в конец. |
| `LocalizationTable` | ScriptableObject с ключами и переводами. Тексты — контент, их правит не программист (D48). Лежит в `Resources`, иначе не загрузится. |
| `Loc` | Статический доступ. Таблица грузится сама при первом обращении — чтобы сцена, запущенная напрямую из редактора, не показывала голые ключи. Язык хранится в PlayerPrefs, по умолчанию английский. |
| `LocalizedText` | На надписи с неизменным текстом: подписи кнопок, заголовки. Строки с числами собираются в коде через `Loc.Get(key, args)`. |

**Пропуск виден сразу:** неизвестный ключ показывается как есть (`menu.newgame`),
пустой перевод откатывается на английский, пустой английский — на ключ.

**Названия контента переводятся через ключ с откатом.** У `BuildingDefinition`,
`BarracksDefinition`, `KingDefinition` и `UpgradeDefinition` рядом с текстом
лежит `nameKey` / `descriptionKey`, а показывается свойство `DisplayName` —
оно зовёт `Loc.GetOrFallback`. Пустой ключ означает «покажи текст из ассета»,
поэтому недопереведённая постройка остаётся читаемой, а не превращается
в `building.tower.name`.

**Ключи проставляются инструментом, а не руками:** меню
`Tools/Локализация/Проставить ключи контента` обходит все дефиниции, строит
ключ по имени ассета (у улучшений — по их `id`, он стабилен) и заводит
недостающие строки в таблице, положив текущий текст в русскую колонку.
Существующие строки не перезаписываются: перевод могли уже поправить руками.
Второй пункт меню — отчёт о том, что не переведено и у каких ассетов нет ключа.

## Техдолг — с причинами

### 1. `EnemyManager` делает три вещи (525 строк)

Сейчас в одном классе: пул-менеджмент (спавн, смерть, `_alive`), расталкивание (сетка, вычисление смещений), поведение (движение, переход в осаду).

Разделение **сначала обсудить**, потом делать. Ориентир: вынести расталкивание в отдельный сервис, поведение оставить, пул-менеджмент оставить. Но резать надо так, чтобы не появилось лишних проходов по списку живых — сейчас он один.

### 2. Раскладка папок ~~разъехалась с namespace~~ — разобрано 4 сентября 2026

Свалка `Addition/` разобрана, `Enemy/` и `Level/` расформированы, `LevelDefinition.cs` переехал из `ScriptableObjects/` в `Waves/`. Ассеты волн уехали из `Scripts/Waves/` в `Assets/WaveResources/` — это контент, ему не место в папке с кодом.

Сейчас **папка = namespace** соблюдается без исключений:

```
Scripts/App        App/UI      Base       Building   Building/UI
CameraRig          Combat      Core       Debugging  Diagnostics
Economy            Enemies     Hero       Input      King
Meta               Squads      UI         Visuals    Waves (+ Waves/Editor)
```

Правило теперь не пожелание, а состояние: новый файл кладётся в папку своего namespace, иначе раскладка снова поедет.

### 3. Разрушаемость построек: не хватает только восстановления

**Запись «поведения врагов нет» устарела** — проверено по коду 5 сентября 2026.
Враги ломают то, что стоит на пути (`EnemyManager.FindBlockingBuilding`,
D41), у построек есть руины и цена восстановления (`Building.ruinsPrefab`,
`RebuildCost`, D42), у поселения есть домики-цели (`NeutralHouse`, D112)
и престиж за уцелевшие (`PrestigeTracker.perHouse`).

Не сделано ровно одно: **восстановить постройку из руин нельзя** —
`Building.RebuildCost` не вызывается ни из одного файла. Руины остаются
на слоте навсегда, и слот выбывает из игры до конца забега.

### 4. Flow field отсутствует

Враги идут по прямому вектору к цели. Точка замены помечена в коде — `EnemyManager.ResolveDirection()`. Без flow field не работает D84–D85 (шахматная застройка, обход препятствий).

### 5. Нет координатора экранов

Победа и поражение переключаются через `SetActive` в `GameHud`, пауза и подсказка управления живут на своих канвасах с явным `sortingOrder` (400 подсказка, 500 пауза, 600 окно клавиш, 1000 переход между сценами). Пока это работает, потому что порядок задан числами в одном месте — в самих классах.

Слой-координатор понадобится, когда появятся перебивки между актами и экран прокачки посреди забега: сейчас никто не гасит контекстные панели при открытии модального экрана, и панель строительства останется висеть под паузой.

### 6. Враги и союзники не расталкивают друг друга

Механизмы разные: враги — через `SpatialGrid`, союзники — через `OverlapSphere`. Внутри своей фракции всё работает, между фракциями — проходят насквозь. Может быть заметно в ближнем бою.

Варианты: дать врагам триггер-коллайдер и учитывать их в `SquadUnit` (дёшево, асимметрично) или свести обе фракции в одну сетку (правильно, дороже).

### 7. Мёртвый код

`Squad.DisbandAll()` — не вызывается нигде. `Squad.commanderId` — зарезервирован под D19, не используется. `Barracks.IsBuilding`, `Barracks.BuildProgress` — под будущий индикатор над постройкой. `Enemy.Deactivate()`.

Не удалять бездумно: часть зарезервирована осознанно.

## Что не трогать без просьбы

**Конструктор волн.** Работает, настраивается дизайнером через ассеты. Менять API — значит ломать уже собранные уровни.

**`SceneContext` и `GameState`.** Только что введены после ревью, на них завязано всё остальное.

**Файлы Unity.** `.unity`, `.prefab`, `.asset`, `.meta` — не редактировать как текст. Новый скрипт = новый `.meta`, который сгенерирует только редактор.

## Правила работы

**Одна задача за раз.** Диф на 400 строк невозможно осмысленно проверить.

**Крупное — сначала план.** Разрезание `EnemyManager`, координатор экранов, flow field — сначала согласовать разбиение.

**Не «заодно».** Заметил постороннее — вынести отдельной задачей.

**Ссылаться на номера решений.** «Сделай D85» точнее, чем «сделай обход препятствий»: в решении есть и формулировка, и предупреждение про maze-abuse.

**Держать правило гейтов.** Не писать код эпика, пока не пройден гейт предыдущей фазы. Сейчас не пройден **Гейт 1** — способности, прокачка и мета кодом не трогаются.

**Комментарии на русском, объясняют «почему», а не «что».** Ссылка на решение в скобках, если оно есть: `// Оплата вперёд (D21a): иначе бойцов можно получить даром`.
